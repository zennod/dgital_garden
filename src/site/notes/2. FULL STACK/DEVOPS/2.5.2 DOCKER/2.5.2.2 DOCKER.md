#docker #devops 
- **DOCKER** is a **CONTAINER** *(i.e. ISOLATED ENVIORNMENT)* platform to *create, manage, scale, test & deploy application.* 
- Every Docker will have **run-c** & **container-d** 
# DOCKER ARCHITECTURE 
- There are 3 Components in the **DOCKER ARCHITECTURE**.

![Pasted image 20240413214521.png](/img/user/_resources/Pasted%20image%2020240413214521.png)
## DOCKER RUNTIME 
- It basically allows us to **START** & **STOP** containers.
- The RUNTIME is of two types - 
	1. *LOW-LEVEL RNTIME* 
		-  Known as **runc**
		- The role of **runc** is to *work with the OS*; Also, **STARTS & STOPS the containers**
	2. *HIGH-LEVEL RUNTIME*
		- Known as **containerd**.
		- The role of **containerd** is managing **run-c**; Also, helps in **managing containers**.
## DOCKER ENGINE  
- Docker Engine is used to INTERACT with the DOCKER. 
	1. **DOCKER DAEMON** - 
		- **DAEMON** - *It's a background process that operates autonomously, performing tasks without user interaction.*
		 - It has 3 parts : -
			![Pasted image 20240413222439.png](/img/user/_resources/Pasted%20image%2020240413222439.png)
		1. **SERVER/DAEMON** - The server response to the request made by **CLIENT**.
		2. **REST API** - API which helps in *COMMUNICATING* to *DAEMON/SERVER*. 
		3. **DOCKER CLI** -  The *DOCKER CLI* will help you send **COMMANDS** via **API** to **SERVER/DAEMON.**
## ORCHESTRATION 
- Orchestration helps in the *managing DOCKER CONTAINER*.
