- *Polymorphism means* **SAME NAME FUNCTIONs** *with* **DIFFERENT FORMS**.
***
# There are 2 Types of Polymorphism : -
## 1. STATIC POLYMORPHISM (OVER-LOADING | COMPILE TIME)
- Also known as **COMPILE TIME POLYMORPHISM** 
	- Because it'll be decided on the *COMPILE TIME* that which **function** should run.
- It doesn't depend on the **RETURN TYPE**.
***
### FUNCTION OVERLOADING
- A technique that allows to have
	- **MORE THAN ONE FUNCTION** with **SAME NAME** in the **SAME CLASS**
	- But it should *DIFFER* in **PARAMETER TYPE** & **NUMBER OF PARAMETER**.
#### Example : - 
```java
 public void displayInfo(String name) {
 System.out.println(name);
 }

public void displayInfo(int age) {
 System.out.println(age);
}

public void displayInfo(String name, int age) {
System.out.println(name);
System.out.println(age);
 }

// Order of the type can be differ
void sum(int a, String b){
}

void sum (String b, int a) {
}
```
***
***
## 2. DYNAMIC POLYMORPHISM (OVER-RIDING | RUN TIME)
- Also known as **RUNTIME POLYMORPHISM**. 
- Also , called as
	- *TOP - CASTING* - **`Parent_class var_name = new Child_class`**
	- *LATE BINDING*

> [!tip]
> - Final Keyword is used to create **CONSTANTS**
> - You can't over-ride a method which is **`final`**. 
>	- **`final void area()`**
***

***
### FUNCTION OVER-RIDING
- When 2 or more *function* with **SAME NAME & SAME SIGNATURE** (*i.e. Return type, Parameters, etc*) exist in **BOTH CHILD & PARENT CLASS**.
	- We use **FUNCTION OVER-RIDING**
	- That is - The **CHILD CLASS** *METHOD/FUNCTION* is ran over the **PARENT CLASS** *METHOD/FUNCTION*.

- Working of *FUNCTION OVER-RIDING*
	1. If exists 2 or more *function* with **SAME NAME & SAME SIGNATURE** 
	2. And a **OBJECT** of **CHILD CLASS** is created & called
	3. The **CHILD FUNCTION** *will OVER-RIDE the* **PARENT FUNCTION**.
		- Meaning -  It'll process the *CHILD FUNCTION* **FIRST** then the *PARENT FUNCTION.*
***
```Java
// General form
Parent_class var_name = new Child_class // TOP-CASTING

// or 
Parent_class var_name = new Parent_class

```

> [!NOTE]+ 
You can't **CALL** the **CHILD FUNCTION** *by using* **PARENT OBJECT**
> 	**`Child_class var_name = new Parent_class`**
> 	**`var.child_func()`**

***
### Example (OBJECT OF PARENT CLASS)
```java
Animal dog = new Dog();
dog.dogfeature();
```
- Making parent object and pointing to the parent class. Here the method / function(which has same signature) of parent class will be called.
***
### Example (OBJECT OF CHILD CLASS)
```Java
Dog dog_C = new Labrador();
dog_c.dogfeature();
```
- making *child class object* and *pointing to the parent class*. Here the **METHOD/FUNCTION** (which has same signature) of **CHILD CLASS** will be *called*.
***
### Example 
```JAVA
class Car{
	public void start(){
	 sout("Car-Start")
	};

	public void stop(){
	sout("Car-Stop")
	};
}
----------------------------------------------------------
// Child Class

class Nissan extends Car{
	@Override            //overriden method
	public void start(){ 
	 sout("Nissan-Start")
	};

	// non-overriden method
	public void gt_edition(){
	sout("Has A GT Edition")
	};
}
----------------------------------------------------------
// Main file
// Dynamic Polymorphism (Can access Overriden & Common methods)
Car c1 = new Nissan();
c1.start(); // Output - Nissan-Start [Calls the Child class method]
c1.stop(); //Output - Car-Stop [Calls the Parent class method]
c1.gt_edition() //Output - Error [Can't call the child method from parent object]

```

# DYNAMIC METHOD DISPATCH
- It represents that which method should be CALLED & RAN on the runtime
	-  Basically an *overridden method is resolve* (*decide*) at **run-time**
- Java will *decide* which method to **EXECUTE** at **RUN-TIME**

> [!question]
> **Q]** How Java will decide which function to be called?
> **Ans** - Java determines which version of method to be **called** based on the **type of the object**
