#java #Object_Oriented_Programming 

- It's a just a **UNWANTED EVENT** which **INTERRUPT** the *flow of code*
- It's the way to handle the **RUNTIME ERRORs.**
# TYPES OF ERROR 
## 1. SYNTAX ERROR 
- Error which occur in the **SYNTAX** of the code
***
## 2. LOGICAL ERROR 
- Error which occurs in **LOGIC** of the *CODE*.
- Will **RUN** but give **OUTPUT** *different* than the expected output
***
## 3. RUNTIME ERROR 
- Error which occurs at the **RUNTIME**
***

# EXCEPTION 
- This represents the handling of some **EXCEPTIONAL CASE** to be **HANDLED**.
- Its an **OBJECT** which is **THROWN** at *runtime.*
- To Handle this situation we add a **TRY CATCH BLOCK**
> [!note]
> Always use multiple EXCEPTION handling for better error catch.

```Java 
try{
	actual_logic
}
catch(type1_of_exception | type2_of_exception its_object ){  
	
}
catch(Exception e){
	System.out.println(e);
}
```

- **`e`** refers to the object variable name of the **TYPE OF EXCEPTION**.

```Java
public static int divide(int a, int b){
	try{
		return a / b;
	}	
	catch(ArithemticException | NullPointerException e){ 
	  
		return -1 
	}
	catch(Exception e){
		System.out.println(e);
	}
}
```

```Output
java.lang.ArithmeticException: / by zero
```

- The output happens to be like this because the TYPE OF EXCEPTION has it own **`toString()`** methods.
