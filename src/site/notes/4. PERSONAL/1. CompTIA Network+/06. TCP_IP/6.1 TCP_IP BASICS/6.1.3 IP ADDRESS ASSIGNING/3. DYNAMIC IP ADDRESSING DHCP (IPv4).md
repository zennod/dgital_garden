## Dynamic IP addressing via the Dynamic Host Configuration Protocol (DHCP) automatically assigns an IP address whenever a computer connects to the network.
* * *
- ***DHCP works very simply.***
- ***Any network using DHCP consists of a DHCP server and DHCP clients.***
- ==The DHCP Servers use UDP on PORT 76 & the DHCP Client use PORT 68.==
- ***Clients request IP information from DHCP servers. DHCP servers in turn pass out IP information to the clients***
- ***Most network have a Single DHCP Server built-in into a ROUTER for small office/home office (SOHO) network.***
- ***In the enterprises a DHCP server might be a Rack - Mounted Server.***
* * *
## HOW DHCP WORKS :-

1. It works on the ***==FOUR - WAY HANDSHAKE==***  OR ***==DORA==*** which is referred as ***==Discover, Offer, Request & Acknowledgement==***.
2. When a client connects to a DHCP Server, the client automatically sends a ***==DHCP Discover message.==*** *(Its just a request)* 


![14e82fd01811be812b8fd7c817365342.png](/img/user/_resources/14e82fd01811be812b8fd7c817365342.png)

3. The ***DHCP hears the request*** & sends back the ***DHCP OFFER*** message *(includes IP address, subnet mask & gateway)*.
4. Then the ***DHCP client*** sends out the ***DHCP REQUEST*** - *as it accepts the IP information.*

	- **==The DHCP Request is very important as it implies that the client has accepted the IP info. from only this DHCP Server.==**

![f0f7ef559ff5a546a202f7310226727e.png](/img/user/_resources/f0f7ef559ff5a546a202f7310226727e.png)

5. Then the ***DHCP Server sends the DHCP ACK (Acknowledgement) & mention's the client's MAC address & IP information in the database.***
6. ***At the End, the DHCP Client's get a DHCP lease from the DHCP pool.***
7. ***A DHCP lease is set for a fixed amount of time; Near the of the lease time, the clients send another DHCP Request.*** 
8. The ***DHCP Server*** looks the ***MAC Address in the database*** & Gives the ***DHCP client the same IP information.*** **==[The renewal process is UNICAST]==**

* * *

# DHCP CONFIGURATION :-

## 1. DHCP Client - 

- *DHCP client is simple. Most times, Every host is **pre-configurated** as a DHCP Client by Default.*
* * *
## 2. DHCP Server - 

- Here, We need to perform some Configurations

	- Create a ***pool of legit IP addresses*** for the clients.
	- It must have ***SUBNET*** for the network pool.
	- It much have an IP address for the ***Default Gateway*** for the network.

- The Installed pool of IP Addresses is called as ***DHCP SCOPE***. The DHCP Scope also includes ***information such as Default Gateway, DNS, Network Time Server - known as Scope Options.***

* * *

## 3. DHCP Relay - 

- ==DHCP Relay Agent allows the devices to connect to the other devices which aren't directly connect to the same network as the DHCP Server.==
- *In other words, if you have 2 networks & by default the broadcast can't travel between networks. Therefore, the DHCP Relay comes into play.*
- ***Basically DHCP Relay Agent passes messages between the devices & the DHCP Server. Thus allowing the DHCP Message to travel between different network.***

![4991382a71fb5b72a87a08bb541e3877.png](/img/user/_resources/4991382a71fb5b72a87a08bb541e3877.png)

- To make a ***DHCP Relay work***, you need to give the ***==IP address of the REAL DHCP Server.==*** This address is known as the ***==IP helper address.==***

* * *

## 4. DHCP Reservation :-

- ==Many Host in network needs a stable or a fixed IP address. For ex - Printer, Workstation, switches, server, etc.==
- You can create a ***separate range*** for these devices.
- There are 2 approach for managing these static IPs.

	- The First, one is to configure each host with a static address.
	
		- *One way to reserve is to reduce the range size of the pool of assignable addresses to avoid that range.*
		- *The other way is to snatch out some of the addresses inside the pool by creating a* ***IP exclusion range***.

![e96f58f2fe71c61b28fb5cf7649dcb9d.png](/img/user/_resources/e96f58f2fe71c61b28fb5cf7649dcb9d.png)

- *The Other approach is that the DHCP Server sets up a **MAC RESERVATION** - **allowing DHCP to lease the same IP addresses to the same host each time.***


![05efd6eb72929a51a4f89b8ff4ab002f.png](/img/user/_resources/05efd6eb72929a51a4f89b8ff4ab002f.png)

* * *

## 5. DHCP Problems.

- When the DHCP Server breaks, the user won't get any IP information. 

### 5.1 No DHCP Server - 

- *When a DHCP Clients tries to get IP information & fails; It'll assign itself with strange address.*
- *The Strange IP address is generated by a version of zero-configuration networking(zeroconf)*

> ***ZEROCONF allows you to automatically create a network of devices without having to manually configure a DHCP server for each device you want to connect to that network***

![691aa888bc745f0234942dc80640c0f0.png](/img/user/_resources/691aa888bc745f0234942dc80640c0f0.png)

- Mircosoft's Implementation is called ***Automatic Private IP Addressing (APIPA)***.  

	- *All the host are designed to generate APIPA address automatically; If didn't receive any response to a DHCP Discover message.*
	- *The host only generates the last 2 octets of an APIPA address; allowing the client to communicate with other nodes as they are on the same network.*
	- *As APIPA can't issue a Default Gateway. Therefore, you won't be able to use the Internet*.

- You can Solve the issue by ***CMD Prompt*** - 
 

	- **For Windows** - *ipconfig /release OR ipconfig /renew*
	<br>
	- **For macOS** 
		 - *To RELEASE : sudo ifconfig eth0 down*
		- *To RENEW : sudo ifconfig eth0 up*
<br>
	- **For LINUX** 
		- *To RELEASE : sudo dhclient -r*
		- *To RENEW : sudo dhclient*
* * *
## 6. Multiple DHCP Servers -

-  *Only one DHCP wont be enough at any kind of failure of network. If the servers dies, no one can access the internet.*
-  ==So, to avoid this kind of issue, the bigger networks - enterprises -  uses more than one DHCP SERVER.==
-  For Ex - The ***network ID is 172.13.14.0***
		
	-	***DHCP Server 1 : Scope 172.13.14.2 to 172.13.14.50***
	-	***DHCP Server 2 : Scope 172.13.14.51 to 172.13.14.100***
- Each would have same subnet mask, default gateway, etc.
* * *
## 7. Rogue DHCP Server -

- ==Its an DHCP Server which provides incorrect IP information to the clients.==
- **This can be done in 2 ways** - 
			
	-	*Firstly, someone in the company might connect the home router into the network* 
	-	*Second, If someone is trying to attack the network.*
- ***An easy to detect a unintentional rouge server. As the router has the default network ID of 192.168.1.0/24***
- Let's assume the network id of the original server is ***10.11.12.0/24*** & a user complaints that the ***internet isn't working***.
- You go & run ***ipconfig/ifconfig*** & see the change in the IP information. That's the spot where you can guess the ***rogue DHCP Server***.
- A ***malicious Rogue DHCP servers*** are sometimes hard to recognize as it uses the same scope as the ***original DHCP server***, but change in ***Default Gateway.*** Therefore, you can be recognizes the ***Rogue DHCP Server.***
